# Conventions

This is a public package, so it does **not** follow the Fullphysio monorepo's
no-comments or 120-column rules.

- `///` dartdoc is **required** on every exported symbol. pub.dev scores it and
  IDE hovers depend on it.
- No comments on private implementation code. Name things properly instead.
- Formatting is stock `dart format` — **default width, no `--line-length`**.
  That is what `pana` and pub.dev expect with zero configuration. A local
  formatter can disagree with stable; CI runs official stable and is the arbiter.
- `dart analyze --fatal-infos` must be clean.
- `lib/` must not import `dart:io` outside `lib/src/platform_io.dart`, or the
  package loses web support and pana points.

## Tests

Three tiers:

- **Unit and conformance** — `MockClient`, no network.
- **Mock server** (`test/mock_server_test.dart`) — a real `HttpServer` on
  loopback with the default `http.Client`: gzip, headers and timeouts on the
  wire. Part of the default run.
- **Integration** (`test/integration/`) — hits a live data plane. Tagged
  `integration` and skipped by default (see `dart_test.yaml`). Run them with:

  ```
  RUDDERSTACK_TEST_WRITE_KEY=<key> RUDDERSTACK_TEST_DATA_PLANE_URL=<url> \
    dart test --tags integration --run-skipped
  ```

  They skip themselves when those variables are unset, so a fresh checkout
  passes. Point them at a test source: the events are real.

## Conformance with @rudderstack/rudder-sdk-node

`test/fixtures/*.json` were generated by `tool/capture_fixtures/capture.js`,
which drives the real `@rudderstack/rudder-sdk-node` (3.0.3) against a local
HTTP server. When changing message construction, validation or retries,
regenerate the fixtures against the same reference version rather than editing
them by hand, and bump the version recorded in `THIRD_PARTY_NOTICES` and the
README if you move to a newer upstream.

## CI

- `ci.yml` — format, analyze, `pub publish --dry-run`, then tests on the declared
  SDK floor and stable, plus a `pana` job that fails if the pub.dev score drops
  below maximum. Runs weekly too, to catch SDK and dependency drift.
- `integration.yml` — live data plane tests on main, nightly and on demand.
  Deliberately not on pull requests: an upstream outage must never block a
  merge.
- `publish.yml` — releases on a `v<version>` tag via GitHub OIDC. No stored
  credentials.

## Releasing

1. Bump `version:` in `pubspec.yaml` and `lib/src/version.dart`, and add a
   `CHANGELOG.md` entry.
2. Merge to `main` and let CI go green.
3. Tag and push:

   ```
   git tag v1.2.3 && git push origin v1.2.3
   ```

Publishing is permanent: a version can be retracted within 7 days but never
deleted, and the number is never reusable.
